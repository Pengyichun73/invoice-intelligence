# Invoice Intelligence 总览 Dashboard 设计规格

## 目标

为审核与治理人员提供一个安静、精准、风险优先的首屏工作台。首屏只展示影响决策的核心业务信号，并把用户最快引导到待处理队列。

## 采用方案

采用“待办队列优先”布局：

- 顶部保留现有双层导航和受控工作区状态。
- 首屏指标仅保留待处理、今日完成、有效案例、开放冲突四项。
- 主区域左侧展示真实待办队列，右侧展示服务状态与数据读取状态。
- 主操作为“进入待处理队列并开始审核”，跳转到现有发票提取视图。
- 任意聚合接口失败时显示“未读取”和可执行的重新读取动作，不显示虚构的零值或进度。

## 数据流

`Dashboard.vue -> frontend/src/api/client.js -> frontend/src/api/invoice.js/governance.js -> FastAPI Application Service`

页面只消费现有 API Client，不直接访问数据库、Milvus、LangGraph 或模型 SDK。写操作不在总览页伪造业务状态，成功后由目标页面重新读取权威状态。

## 交互与动效

- 沿用现有 Vue `Transition` 页面切换，退出比进入更短。
- 只对 `transform` 和 `opacity` 做过渡。
- 待办列表使用稳定网格，避免动画改变布局尺寸。
- 支持 `prefers-reduced-motion: reduce`，降级为空间位移关闭、透明度快速切换。
- 操作按钮与核心触控目标不低于 44px。

## 错误与状态

- 加载：显示结构稳定的骨架状态。
- 空结果：明确显示“当前没有待办”，但仅在 API 成功返回空集合时使用。
- 读取失败：显示受控中文错误和“重新读取”动作。
- 429/503/409：复用现有错误白名单与通知机制，不展示远端原始响应体。
- 后端未实现或未读取的状态不得由前端推断为已完成。

## 视觉方向

- 延续现有深色运营台设计、青绿色技术强调色、黄/红风险色。
- 保持 8px 以内圆角、紧凑信息密度和高对比键盘焦点。
- 不新增装饰性渐变、玻璃效果、品牌营销文案或无业务价值的图表。

## 验收范围

- Dashboard 首屏信息层级符合待办优先方案。
- 主按钮能导航到发票提取视图。
- Dashboard 的读取状态区分 loading、成功空结果、失败和未读取。
- 现有移动端布局不产生横向溢出。
- 只运行与本次变更直接相关的前端构建和验证命令。
