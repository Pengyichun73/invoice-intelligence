# Invoice Intelligence 任务中枢前端设计

## 目标

将现有 Vue 3 管理界面重构为面向同一位业务审核与治理人员的“任务中枢”。第一屏优先回答：系统是否可用、现在需要处理什么、哪类风险优先、下一步去哪里操作。保留现有真实能力，不模拟后端进度，不宣称未实现功能。

## 设计原则

- 当前图片证据、待人工处理任务和业务结果优先于技术元数据。
- 客户可理解的中文状态统一由展示层映射，后端稳定英文枚举不变。
- 授权业务字段完整展示，不使用星号遮蔽；图片 Base64、Prompt、API Key、向量和跨租户数据仍禁止展示。
- 高信息密度页面保持可扫描性，版本、资源 ID、Trace、错误码和投影详情进入详情区或技术信息折叠区。
- 使用冷黑与深青为工作背景、荧光黄绿作为主行动强调色、青绿表示健康状态、琥珀表示需人工注意、红色仅表示失败或危险操作。
- 动画只用于页面进入、真实状态变化、加载和操作反馈；持续时间 150-300ms，并尊重 `prefers-reduced-motion`。

## 信息架构

桌面端使用双层顶部导航，替换常驻侧边栏：

1. `工作台`：总览、发票提取。
2. `可信记忆`：记忆准入、案例库。
3. `字段语义`：字段目录、冲突处理。
4. `运行治理`：索引、评估、审计。

移动端使用紧凑顶部栏与底部核心导航；低频功能进入功能菜单。路由状态继续由当前应用内部状态管理，不为本阶段引入 Vue Router 或 Pinia。

## 首页结构

1. 顶部显示服务真实健康状态和主要导航。
2. 首屏标题聚焦“先处理需要人工判断的事项”，主按钮进入上传提取。
3. 摘要指标包含待人工处理、今日已完成、可信案例和多源识别状态。
4. 待办队列按字段冲突、识别冲突、记忆准入等风险排序，并链接到对应页面。
5. 右侧展示文件处理、识别、记忆检索和治理审计的可用状态。
6. 技术信息、索引状态和审计记录作为次级入口，不占据客户第一注意层级。

总览仅展示后端真实返回的数据。接口不可用时显示“未读取”或“部分数据不可用”，禁止用 `0` 伪装成功响应。

## 页面职责

- 发票提取：上传、固定 Workflow 阶段、完整字段结果、视觉证据、文字识别对比和人工审核。
- 记忆准入：待办优先，支持状态筛选、详情、单条/批量决定和重新评估。
- 案例库：明确区分确认正确、人工纠正和确认错误，展示 PostgreSQL 投影登记状态。
- 字段语义：展示标准字段、描述、上下文锚点、已批准别名和待审批候选。
- 冲突处理：展示冲突候选、证据来源并提交解决或忽略决定，成功后重新读取后端状态。
- 索引治理：分开案例索引与字段语义索引，明确“登记、投影、激活”的差异。
- 评估：以方案对比和风险指标为核心，不提供自动晋升。
- 审计：支持操作、资源、时间和 Trace 筛选；Trace 明确标记为技术关联标识。

## 组件边界

- `AppShell`：顶部全局导航、二级导航、移动菜单和全局服务状态。
- `TaskSummary`：首页指标和未知状态处理。
- `PriorityQueue`：跨治理域的可行动摘要，不伪造统一后端任务流。
- `StatusBadge`：稳定枚举到中文标签和视觉语义。
- `DetailDrawer`：客户摘要与技术详情分层。
- `DataTable`：分页、加载、空状态、错误状态和移动端降级。
- `ActionDialog`：危险操作原因、revision 和等待状态。
- `ResourceState`：统一 403、409、422、429、500、503 错误表达。

组件只消费 View Model，不直接访问 API。所有请求继续集中在 `frontend/src/api/`。

## API 接入

保留现有接口并完善前端消费：

- 总览：健康、准入列表、案例列表、冲突列表、OCR 指标。
- 提取：上传、启动提取、运行状态、结果、审核请求和审核提交。
- 准入：列表、详情、单条决定、批量决定、重新评估。
- 案例：列表、详情、单案例投影、禁用。
- 字段语义：目录、冲突、冲突决定、别名决定。
- 案例索引：登记重建、查询、执行投影、激活。
- 字段语义索引：登记、查询、执行投影、激活。
- 评估与审计：按现有只读契约查询。

写请求继续由集中 Client 自动生成 `Idempotency-Key`。revision 必须来自最新服务端响应；409 后重新读取记录，不在前端覆盖状态。tenant 和 reviewer 不提供可编辑输入，必须来自可信请求上下文。

## 数据流

```text
用户操作
  -> View 组装非敏感请求参数
  -> 集中 API Client 添加 Idempotency-Key
  -> FastAPI Router
  -> Application Service
  -> PostgreSQL 权威状态
  -> Presenter Response
  -> View Model 中文化与分层展示
```

前端不得直接查询 PostgreSQL、Milvus、LangGraph 或模型。`indexed` 仅表示 PostgreSQL 记录过一次成功投影，不表示当前请求实时验证了 Milvus。

## 错误与恢复

- `403`：显示权限或二级审批规则限制。
- `409`：提示数据已更新，重新读取最新 revision。
- `422`：在对应字段附近显示校验原因。
- `429`：显示限流提示并保留用户输入。
- `500`：显示通用失败信息和可用 Trace，不暴露异常正文。
- `503`：显示服务降级，不把缺失数据显示为零。
- 长任务只轮询后端实际状态；超时后保留资源 ID，允许用户稍后恢复查询。

## 响应式与可访问性

- 验证 375、768、1024、1440 像素视口。
- 正文最小 16px（移动端），交互目标最小 44x44px。
- 键盘焦点清晰，导航顺序与视觉顺序一致。
- 颜色不是唯一状态依据，状态同时显示图标或文字。
- 表格在窄屏转为字段分组列表，禁止横向溢出遮挡核心操作。
- 尊重减少动态效果设置，关闭非必要位移和循环动画。

## 验证策略

- 运行现有前端构建，确认 Vue 编译、依赖和生产资源生成正常。
- 对集中 API Client、枚举中文化、revision 409 恢复和 Idempotency-Key 做定向测试。
- 使用 Mock API 验证加载、空数据、403、409、429、500、503 和部分接口失败。
- 使用浏览器检查桌面与移动视口、键盘导航、文本溢出和减少动态效果。
- 不调用真实模型、OCR、Milvus 或生产数据库。

## 非目标

- 不修改 `InvoiceExtraction`。
- 不增加新的 Agent、Workflow、数据库或消息队列。
- 不实现后端尚不存在的统一跨域任务聚合接口。
- 不把 Milvus 实时健康状态、Catalog 自动发布或模型自动晋升伪装成已实现能力。
