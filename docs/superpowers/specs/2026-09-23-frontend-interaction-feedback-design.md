# 前端交互反馈增强设计

## 目标

在不改变后端契约、不伪造进度的前提下，让客户明确感知每次操作是否开始、是否成功、失败原因及下一步动作。界面继续保持克制、专业、中文优先。

## 交互架构

1. API Client 通过 `try/finally` 维护并发请求计数，只在 HTTP 活动存在时显示不确定进度；取消、解析异常和并发请求都不能造成计数泄漏。该进度不表示后台 Workflow 阶段。
2. 全局 Notification Center 显示成功、警告、错误和信息反馈；支持关闭、超时、后续动作按钮及 `aria-live`。
3. App Shell 负责真实请求进度、Hash 导航、浏览器前进/后退、页面过渡和页面标题焦点恢复。
4. 页面继续保留与资源绑定的内联错误；写操作额外使用全局反馈，成功后刷新权威后端状态，不进行乐观伪造。
5. Action Dialog 管理焦点、Esc、忙碌状态和提交结果，避免重复提交与误关闭。

## 安全错误与幂等重试

通知和页面错误只能读取前端按 HTTP Status/后端 Code 映射的白名单文案，不显示响应中的任意 `message`、`detail`、完整 payload 或远程响应体。未知错误使用固定泛化文案；受信 `X-Trace-ID` 可作为技术关联标识单独展示。

每次逻辑写操作生成一个 `Idempotency-Key`。网络失败、429 或 503 造成结果不确定时，相同路径、方法和语义请求在当前页面生命周期内复用原 Key；收到成功或确定性非重试响应后释放。Key 仅保存在内存，不进入通知、日志或持久化存储。

409 后必须清空陈旧选择和对话框快照，按资源重新读取后端权威状态与最新 revision；刷新失败时标记“最新状态未读取”，不得使用旧 revision 再次提交。写请求已成功而后续读取失败时，保留“操作已保存”的事实并给出仅重试读取的动作，不能把整个流程显示为写入失败或再次发起写请求。

## 导航与对话框

Hash 仅接受内置视图白名单；非法值使用 `replaceState` 回退总览。初始 Hash 优先于 Local Storage，程序跳转避免重复历史项，浏览器前进/后退驱动当前视图。切换后更新页面标题并聚焦主标题。

对话框打开时聚焦第一个输入，Tab/Shift+Tab 限制在对话框内；提交期间 Esc、遮罩和关闭按钮不可关闭；关闭后恢复触发控件焦点。对话框错误使用 live region 宣告。

## 状态语义

- 成功：说明已落库的权威事实，并提供合理的下一步入口。
- 警告：操作部分完成、需人工继续处理或后端状态发生变化。
- 错误：说明失败及可恢复动作；网络、403、409、429、503 使用稳定中文。
- 进行中：使用不确定进度条或按钮加载状态，不显示虚构百分比。

## 动效规则

- 点击反馈 120-160ms，页面与通知进入 220-300ms。
- 只动画 `transform` 与 `opacity`，避免布局跳动。
- `prefers-reduced-motion: reduce` 下关闭非必要动画。
- 动效不阻塞输入，不替代文字状态与图标。

## 安全边界

不展示完整 Prompt、Base64、API Key、向量、Idempotency-Key 或远程响应体。技术 Trace 仍只作为排障关联标识；页面反馈不得声称 Milvus 实时健康或未返回的后台阶段已完成。
